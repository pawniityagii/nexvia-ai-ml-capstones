# API Documentation

Base URL (local): `http://localhost:8000`
Interactive docs (auto-generated by FastAPI): `http://localhost:8000/docs`

## `GET /health`
Liveness + whether the model is loaded.
```json
{"status": "ok", "model_loaded": true, "threshold": 0.83}
```

## `POST /score`
Score one transaction. Unknown fields are accepted and ignored; missing fields
are imputed. Returns the fraud probability, the decision, and the scoring
latency.

Request (minimum useful fields):
```json
{
  "TransactionID": 1001,
  "TransactionDT": 500000,
  "TransactionAmt": 2500.0,
  "card4": "visa", "card6": "credit",
  "addr1": 300, "P_emaildomain": "gmail.com",
  "DeviceType": "mobile", "DeviceInfo": "new-device#1",
  "id_30": "Android 10", "id_31": "chrome 86.0"
}
```
Response:
```json
{
  "transaction_id": 1001,
  "fraud_probability": 0.9246,
  "decision": "pass",
  "threshold": 0.83,
  "latency_ms": 2.88
}
```
`decision` is `"flag"` when `fraud_probability >= threshold`, else `"pass"`.
The threshold is the PR-curve-tuned value stored in `artifacts/feature_meta.json`.

## `GET /cases?status=open&limit=50`
Scored transactions as analyst cases, ranked by score. `status` is one of
`open`, `confirmed_fraud`, `cleared` (omit for all).

## `GET /stats`
Counters for the dashboard: total scored, flagged, open, confirmed.

## Notes
- The same scoring core (`src/serving/scorer.py`) backs both this API and the
  Kafka consumer, so batch replay and the HTTP path score identically.
- Every scored transaction is written to the SQLite case store the dashboard
  reads.
